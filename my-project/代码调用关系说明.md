# 代码调用关系说明

## 项目整体架构与数据流

本项目是一套“React 统一前端 → Unified Backend 认证/聚合/代理 → AiVision 采集、推理、规则判定与告警”的视觉安全平台：摄像头帧进入共享内存后被普通检测消费者、物流通道运行时或独立视觉集成处理，结果再经证据录制和告警分发返回统一后端与前端。

目录职责：

- `scripts/`：环境探测、密钥准备、tmux 服务启停、状态检查和迁移/构建验证。
- `unified_frontend/`：React 页面、权限、Hooks、API 客户端、监控与配置组件。
- `unified_backend/`：登录认证、权限中间件、访问审计、告警聚合/处置，以及对 AiVision、保安室和 Security VLM 的代理。
- `auth/`：统一后端与 AiVision 共用的 JWT、用户、角色和部门权限能力。
- `AiVision/core/`：配置、数据库、缓存、事件总线、日志、进程清理和告警通道。
- `AiVision/platform/`：相机、推理、部门、物流通道、违规证据和系统总编排。
- `AiVision/features/`：通过 `FeatureSpec` 注册的检测功能及其 ORM、Schema、Service、Consumer。
- `AiVision/integrations/`：保安室行为检测与 Security VLM 多摄像头/多部门处理。

## 入口文件清单与启动顺序

### 持续运行入口

1. `scripts/start.sh` 执行参数解析、依赖/配置预检、共享 `AUTH_SECRET` 准备和旧会话清理，然后按 `SERVICES` 数组顺序调用 `start_one`。
2. `AiVision/main.py`：以 `python main.py --host 127.0.0.1 --port 7862` 启动；设置 multiprocessing `spawn`、限制 OpenCV 线程、创建 `Orchestrator`，再启动 Uvicorn。
3. `unified_backend/run_server.py`：以 `python -m unified_backend.run_server --host 127.0.0.1 --port 5000` 启动；装配统一 FastAPI 应用、用户库、审计库和异步代理客户端。
4. `unified_frontend/src/main.tsx`：由 `npm run dev -- --host 0.0.0.0 --port 3000` 交给 Vite 加载；挂载 `AuthProvider`、`ProtectedRoute` 和 `App`。
5. 启动脚本随后检查 AiVision `/api/v2/runtime/health`、统一后端 `/api/health` 与前端端口；任一服务失败时保留其他服务并输出针对性日志。

说明：`AiVision/integrations/guard_room/src/server.py` 与 `AiVision/integrations/security_vlm/src/main.py` 也可作为独立 ASGI/进程入口；当前统一启动拓扑不再把 `guard_room`、`security_vlm` 作为独立 tmux 主服务，而由视觉服务管理层衔接。`legacy_data_migration.py`、`draw_roi.py`、`build-overview-mascot.py` 及各测试文件属于工具/验证入口。

## 核心调用链

### AiVision 启动与相机采集

- `AiVision/main.py::main` → 调用 → `platform.orchestrator::init_orchestrator`（作用：创建系统唯一编排器）。
- `AiVision/main.py::main` → 调用 → `Orchestrator.start`（作用：按顺序初始化数据库、配置、告警、相机、推理、物流通道和功能消费者）。
- `Orchestrator.start` → 调用 → `CameraManager.initialize_configs`（作用：把数据库摄像头配置转换为跨进程共享对象）。
- `Orchestrator.start` → 调用 → `CameraManager.start_all`（作用：逐台启动启用的摄像头并启动看门狗）。
- `CameraManager.start_all` → 调用 → `CameraManager._start_one`（作用：构造单摄像头运行时、注册共享帧并处理启动异常）。
- `CameraManager._start_one` → 调用 → `CameraRuntime.start`（作用：创建以 `_capture_loop` 为目标的采集子进程并等待就绪）。
- `CameraRuntime._capture_loop` → 写入 → 双缓冲共享内存（作用：持续发布最新帧与帧序号）。
- `Orchestrator.start` → 调用 → `FrameReaderRegistry.start_all`（作用：把共享内存帧转换为进程内最新帧视图，供消费者与接口读取）。

### 模型推理、普通检测与告警

- `Orchestrator.start` → 调用 → `InferenceManager.initialize_queues` → `InferenceManager.start_all`（作用：建立推理/结果队列并启动模型工作进程）。
- `Orchestrator._start_consumers` → 调用 → `Orchestrator._start_consumer`（作用：根据 `FeatureSpec`、功能开关和已运行模型实例化消费者）。
- `Orchestrator._start_consumer` → 调用 → `FeatureSpec.consumer_cls(...).start`（作用：启动具体检测功能的消费线程）。
- `BaseFunctionConsumer.start` → 调用 → `BaseFunctionConsumer._run`（作用：循环读取摄像头帧、配置和异步推理结果）。
- `BaseFunctionConsumer._run` → 调用 → `_process` / `dispatch_inference_sync` / `_collect_async_results`（作用：完成规则计算、向模型派发任务并收集结果）。
- `BaseFunctionConsumer._process` → 调用 → `post_process` / `_handle_alarm`（作用：生成标注帧并决定是否形成告警）。
- `BaseFunctionConsumer._handle_alarm` → 调用 → `AlarmDispatcher.maybe_dispatch`（作用：应用冷却规则并提交声光、企业微信和违规证据处理）。
- `AlarmDispatcher.maybe_dispatch` → 调用 → `AlarmDispatcher._execute`（作用：执行告警设备、图片/视频写入及异步微信发送）。

### 物流通道

- `api/v2/logistics_channels.py` 路由 → 调用 → `LogisticsChannelService` 的创建、更新、绑定、移动或删除方法（作用：在事务和锁保护下维护通道/成员关系）。
- `LogisticsChannelService._notify_channel_changed` → 发布 → `config_event_bus`（作用：把数据库变更通知运行时；回调绑定属动态分发）。
- `Orchestrator._on_config_change` → 调用 → `LogisticsChannelRuntime.refresh_channel` / `refresh_camera_all`（作用：热刷新通道视图与摄像头成员）。
- `LogisticsChannelRuntime._evaluation_loop` → 调用 → `_snapshot_channel` → `_prepare_view` → `_compose`（作用：读取成员快照并合成通道画面）。
- `LogisticsChannelRuntime._evaluation_loop` → 调用 → `evaluate` → `_transition`（作用：根据成员在线/检测状态推进通道状态机）。
- `LogisticsChannelRuntime._transition` → 调用 → `_execute_incident` → `_build_alarm_request`（作用：形成单人作业事件、录制证据并交给告警分发器）。

### 保安室与 Security VLM

- `GuardRoomRuntimeManager.start` → 调用 → `_get_or_create_context` → `GuardRoomRuntime.start`（作用：按站点创建配置、状态、通知器和视频运行循环）。
- `GuardRoomRuntime._run_loop` → 调用 → 行为/车辆规则模块 → `AlarmManager.emit`（作用：从视频帧、姿态、制服和车辆状态形成告警事件）。
- `AlarmManager.emit` → 调用 → `AlarmClipRecorder.start_clip` / `AlarmClipRecorder.update`（作用：保存快照并录制告警前后视频）。
- `CameraRuntimeManager.start_all` → 调用 → `_start_runtime` / `_ensure_vlm`（作用：为 Security VLM 摄像头启动采集、检测、会话和 VLM 工作进程）。
- `session_worker::main` → 调用 → `PairSessionManager.step`（作用：在 ROI 内跟踪交互目标并生成待判定任务）。
- `vlm_worker::run_task_worker` → 调用 → `process_queued_item` → `PendingTaskProcessor.process`（作用：按部门/摄像头公平取任务并做幂等处理）。
- `PendingTaskProcessor._process_locked` → 调用 → `VLMJudge.judge`（作用：提交多模态判定、解析结果、保存片段与累计统计）。

### 统一后端与前端

- `unified_backend/run_server.py::main` → 调用 → `unified_backend.app::create_app`（作用：创建 FastAPI 聚合应用）。
- `create_app::lifespan` → 调用 → `UserStore.initialize` / `AccessAuditStore.initialize` / `AsyncProxyClient`（作用：准备认证、审计和上游连接池，并在退出时关闭客户端）。
- `create_app::auth_middleware` → 调用 → `get_current_user_from_request` 与资源权限判断（作用：统一拦截未登录或越权请求）。
- 各 `proxy_*` 路由 → 调用 → `_proxy` → `AsyncProxyClient`（作用：向 AiVision、保安室或 Security VLM 转发同步/流式请求）。
- `unified_frontend/src/main.tsx` 顶层 → 渲染 → `AuthProvider` → `ProtectedRoute` → `App`（作用：恢复登录态并进入受保护页面）。
- `App::renderContent` → JSX 引用 → 各 `*Section`（作用：按权限和当前导航项选择业务页面；CodeGraph 将此边界识别为 React 动态调度）。
- 业务 `Section` → 调用 → Hook/API 客户端（作用：加载配置、状态、告警或媒体数据并维护页面状态）。
- API 客户端 → 请求 → Unified Backend → 代理/聚合 → AiVision 或视觉集成（作用：完成端到端配置、监控和告警数据回流）。

## 关键数据流

1. 摄像头配置从数据库经 `camera_service` 进入 `Orchestrator` 和 `CameraManager`，采集进程把 BGR 帧写入共享内存。
2. `FrameReaderRegistry`、普通 `BaseFunctionConsumer`、物流通道运行时或视觉集成读取帧；需要模型时通过 `InferenceManager` 的队列提交并接收结果。
3. 检测结果更新监控帧/状态；命中规则时由证据录制器保存图片或视频，再经 `AlarmDispatcher`、保安室 `AlarmManager` 或 Security VLM 结果存储形成告警。
4. Unified Backend 聚合各来源告警并执行认证、部门权限、处置状态与审计；React 页面通过 API 客户端/Hook 展示并修改配置。
5. 配置更新写入服务层后通过事件总线或运行时刷新函数热更新相机、消费者和物流通道；无法由静态图确认的框架回调/多态边界在源码注释中标为“待确认”。
